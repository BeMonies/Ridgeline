# Ridgeline — project guide for Claude Code

Ridgeline is a training-program app: an installable web app (PWA) hosted on GitHub Pages.
It shows a day-by-day program, lets the athlete log working weights, and works offline.
Pushing to `main` publishes the site in about a minute. **The repo is public.**

## Layout (everything below is at the repo root)
- `index.html`, `app.js`, `sw.js`, `manifest.webmanifest`, `icons/` — the shipped site
- `programs/index.json` — which program is active, plus the archive and travel file
- `programs/ski-2026.json` — Mountain Athlete Hybrid (active)
- `programs/golden-leaf-2026.json` — archived; opened with `?p=golden-leaf-2026`
- `programs/travel.json` — 7 travel workouts, not tied to dates
- `_source/src/` — app source (`tokens`, `brand`, `data`, `components`, `screens` .jsx)
- `_source/build.sh` — rebuilds `app.js` from source (needs Node 18+)

`app.js` is a **build output**. Never edit it by hand. Edit `_source/src/*.jsx`, then run
`sh _source/build.sh`, and commit source and `app.js` together.

`_source/author_ski.py`, `extract_gl.mjs` and `split_travel.mjs` were one-time generators.
Do not re-run them: they point at paths that don't exist in this layout and would overwrite
hand edits. **The JSON files in `programs/` are the source of truth. Edit them directly.**

## First session housekeeping
Create a `.gitignore` containing `node_modules/` and `_source/src/entry.jsx` (generated by the build).

## Workflow
1. Make the change. If it touches app code, run `sh _source/build.sh`.
2. Preview locally: serve the repo root (`python3 -m http.server 8000`) and open localhost:8000.
   Check today's view, a gym day, a run day, the date overlay, and a log entry.
3. Show me what changed. Only commit and push when I say so.
4. Commit with a clear message and push to `main`. After a push, tell me the live URL to check.

## Data model
- Program days are keyed by Program Week + weekday: `W3-mon`. The calendar date comes from the
  program's `startDate`. Changing `startDate` shifts every date; content doesn't change.
- Day `type`: `gym`, `run`, `rest`, `race`. Optional flags: `optional`, `deload`, `calibration`.
- Items (`k`): `mv` (movement), `interval` (Every X:XX with start marks), `group` (superset),
  `wod` (AMRAP / EMOM / For Time), `flag` (fallback / scaling / regression / isolation /
  stoprule / descent), `note`. Golden Leaf also uses `pair`, `complex`, `cluster`.
- **The training log is keyed by movement name** (normalized: lowercase, punctuation and
  parentheticals ignored). Renaming a movement orphans its logged history. Keep names identical
  across days, blocks and programs. Rename only on purpose, and say so.
- Logs live in each user's `localStorage`, never in this repo.

## Content rules
- **Never put personal data in program files** — PT notes, trips, race dates, body weight, or
  names. Programs are shareable and this repo is public.
- Gym section order is fixed: Warm-Up, Strength Intensity, Conditioning, Finisher, Mobility.
- Run days: Title + TRT headline, collapsed Running Mobility Warm-Up, then the workout.
- Rest is stated per section, using Rest After Exercise / Rest After Round / Interval values.
- Exactly one isolation movement per session, in the Finisher.
- RPE only. Tempo strings display verbatim (e.g. `@3011`).
- **Banned terms anywhere in the UI or content:** Zone 1–5, Week N as a label, Wave, RIR,
  Strength Balance, Contrast Pair / Strip-Set / Same-Load (Golden Leaf archive only).
  Running effort words are Easy / Steady / Threshold / Hard.

## Design rules (see `_source/src/tokens.jsx`)
- Ember `#C05A24` = position and structure. Teal `#4E8A94` = rest, pacing, running. Ink `#1B2426`
  = text. Red is reserved for the emphasis flags (isolation, stop rule, descent) so they stand out.
- Prescriptions (sets, reps, tempo, RPE) use the monospace face. Body copy uses the system sans.
- Never rely on color alone. Touch targets are at least 40px, focus rings stay visible, and
  reduced-motion is respected.
- Mobile first. On large screens the column caps at 560px.
- Logging is the only user input. Don't add accounts, analytics, social features or a backend
  without asking first.

## Service worker
`sw.js` is network-first, so updates arrive the next time the app opens online. If you add a
new top-level file the app needs offline, add it to the `SHELL` list in `sw.js`.
