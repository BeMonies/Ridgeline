# Ridgeline — project guide for Claude Code

Ridgeline is a training-program app: an installable web app (PWA) hosted on GitHub Pages.
It shows a day-by-day program, lets the athlete log working weights, and works offline.
Pushing to `main` publishes the site in about a minute. **The repo is public.**

## Layout (everything below is at the repo root)
- `index.html`, `app.js`, `sw.js`, `manifest.webmanifest`, `icons/`, `fonts/`, `assets/` — the shipped site
- `brand/` — identity kit v1.2 reference (design spec, product requirements, tokens); not shipped to users
- `programs/index.json` — which program is active, plus the archive and travel file
- `programs/mountain-athlete-v3.json` — Mountain Athlete Strength, v3.1, 12 weeks (active)
- `programs/ski-2026.json` — Mountain Athlete Hybrid (archived; opened with `?p=ski-2026`)
- `programs/golden-leaf-2026.json` — archived; opened with `?p=golden-leaf-2026`
- `programs/travel.json` — 7 travel workouts, not tied to dates
- `_source/src/` — app source (`tokens`, `brand`, `data`, `resolve`, `components`, `screens` .jsx)
- `_source/src/resolve.jsx` — pure functions (no React) that pick variants and work out run minutes
- `_source/build.sh` — rebuilds `app.js` from source (needs Node 18+)
- `_source/check.mjs` — content and resolver checks; run `node _source/check.mjs`

`app.js` is a **build output**. Never edit it by hand. Edit `_source/src/*.jsx`, then run
`sh _source/build.sh`, and commit source and `app.js` together.

`_source/author_ski.py`, `extract_gl.mjs` and `split_travel.mjs` were one-time generators.
Do not re-run them: they point at paths that don't exist in this layout and would overwrite
hand edits. **The JSON files in `programs/` are the source of truth. Edit them directly.**

## Housekeeping
`.gitignore` covers `node_modules/` and `_source/src/entry.jsx` (generated by the build).
If you add a file the app needs offline, add it to `SHELL` in `sw.js` and bump `CACHE`.

## Workflow
1. Make the change. If it touches app code, run `sh _source/build.sh`. If it touches a program
   file or `resolve.jsx`, run `node _source/check.mjs` and fix anything it reports.
2. Preview locally: serve the repo root (`python3 -m http.server 8000`) and open localhost:8000.
   Check today's view, a gym day, a run day, the date overlay, and a log entry.
3. Show me what changed. Only commit and push when I say so.
4. Commit with a clear message and push to `main`. After a push, tell me the live URL to check.

## Data model
- Program days are keyed by Program Week + weekday: `W3-mon`. The calendar date comes from the
  program's `startDate`. Changing `startDate` shifts every date; content doesn't change.
- Day `type`: `gym`, `run`, `rest`, `race`. Optional flags: `optional`, `deload`, `calibration`.
- Items (`k`): `mv` (movement), `interval` (Every X:XX with start marks), `group` (superset),
  `wod` (AMRAP / EMOM / For Time), `flag` (fallback / scaling / regression / isolation /
  stoprule / descent), `note`, `sub` (a labelled subsection inside a section, with an optional
  `budget`). Golden Leaf also uses `pair`, `complex`, `cluster`.
- **Variants (programs with `"engine": 1`, i.e. v3).** Any item or section can carry
  `when:{key:value}` and is kept only if every condition holds (an array value means "any of").
  Keys come from `dayVars` in `resolve.jsx`: `wall`, `powerMode`, `lb` (Leg Blaster week),
  `friPower` (`jumps` / `clean` / `throws`), `deload`. `{{name}}` in any string is filled from the
  same variables. Run days carry a `run` spec instead of `parts`; minutes are computed from the
  athlete's own baselines, so run time is never typed into the file.
- **Leg Blasters** are one switch with linked changes (Wednesday WOD, Friday power, Friday
  accessory rounds). `legBlasterAvailable` refuses the option unless all three variants exist.
- **Personal layer** (`ridgeline.personal.v1` in localStorage, edited on the Setup screen): start
  date, run baselines, zone profile, equipment, power mode, Leg Blaster weeks, single-leg rounds
  override. It is never written to a program file and never included in the log backup, which
  contains only `app`, `exported` and `log`. Do not add personal fields to the backup.
- **The training log is keyed by movement name** (normalized: lowercase, punctuation and
  parentheticals ignored). Renaming a movement orphans its logged history. Keep names identical
  across days, blocks and programs. Rename only on purpose, and say so.
- Logs live in each user's `localStorage`, never in this repo.

## Content rules
- **Never put personal data in program files** — PT notes, trips, race dates, body weight, or
  names. Programs are shareable and this repo is public.
- Gym section order is fixed. v3 programs: Warm-Up, Max Strength, Strength Conditioning, Finisher,
  Cooldown Mobility, with a minute budget on each (normal sessions total 60). Older programs keep
  Warm-Up, Strength Intensity, Conditioning, Finisher, Mobility.
- Run days: Title + TRT headline, collapsed Running Mobility Warm-Up, then the workout.
- Rest is stated per section, using Rest After Exercise / Rest After Round / Interval values.
- Older programs: exactly one isolation movement per session, in the Finisher. v3 drops this
  cap and does not use the Isolation badge.
- RPE only. Tempo strings display verbatim (e.g. `@3011`).
- **Banned terms anywhere in the UI or content:** Week N as a label, Wave, RIR, Strength Balance,
  Contrast Pair / Strip-Set / Same-Load (Golden Leaf archive only).
- Running uses a five-zone profile written Z1–Z5 (this replaces the old ban on zone terms and the
  Easy / Steady / Threshold / Hard vocabulary). Show each zone's intent and effort cue. Show the
  athlete's own bpm boundaries only if they entered them; otherwise say "not set". Never estimate
  boundaries or calculate them from age.
- Shared program files must not mention injuries, treatment, clinicians, venues, trips or dates
  other than the default start date. `check.mjs` scans for these.

## Design rules — visual identity v1.2 (full spec in `brand/DESIGN_SPEC.md`; tokens in `brand/ridgeline.tokens.json`)
- Values live in `_source/src/tokens.jsx` (light theme; there is no dark mode yet, and the kit's dark map
  is in the token file for later). Warm neutral surfaces, charcoal text `#1C2628`.
- **Orange `#EB4817` is only** the logo, the one primary action per task area, and the selected date.
  Small orange text uses `#B73610`. Text on orange is near-black `#111718`, never white.
- **Teal organises structure and time:** section headings are 20/26 deep-teal (`#35636B`) on a pale-teal
  band with a 3px `#4E8A94` side rule, all identical; interval/WOD/group cards have a pale-teal header;
  rest and timing are deep-teal lines, not pills. Never give warm-up, strength or conditioning their
  own colours.
- Type is **Inter** (bundled, `fonts/`), tabular numerals only on times, dates and measurements. Session
  title 30/36 700, exercise name 18/24 600, body 16/24, label and caption 14/20. Sentence-case body copy;
  no monospace, no letter-spaced uppercase headings. Michroma exists only inside the outlined wordmark.
- Status uses its own colours plus a symbol and words: success (✓), warning/stop rule (⚠), error (⚠).
  Never orange for errors, never colour alone.
- Touch targets ≥ 44px, primary buttons 48px, field boundaries `#7A8586` (≥ 3:1), one global 3px
  focus ring, reduced motion respected. 4px spacing scale; 20px gutter (16px at ≤ 360px); reading
  column max 720px. No card-in-card-in-card: page, then a related group, then plain rows.
- Required setup and safety text stays visible (`flag` kind `setup`, `stoprule`); only optional
  alternatives collapse (`fallback` → "Alternative exercise or setup").
- Logging is the only user input besides the private Setup screen. Don't add accounts, analytics, social
  features or a backend without asking first. **No run, set or rest timers** — intervals and rest are
  written instructions. A WOD timer is a possible future opt-in, not approved.

## Logging and dates (kit `brand/PRODUCT_REQUIREMENTS.md`)
- Every externally loaded movement has weight entry directly under it (ramp-ups and weighted WOD
  movements too). Fields: weight, lb/kg, reps (rounds for sleds and carries). `basis` on the item says
  what the number means (barbell total incl. bar, per dumbbell, bell weight…); leave it off where the
  programming does not define the implement rather than guessing.
- A set stores the value and unit **as entered** (`w`, `u`), an exact `kg` (1 lb = 0.45359237 kg) and
  `at` (when it was performed). Unit switching converts the display only. Entries are keyed by the
  **planned** date, so opening Oct 6 on Oct 21 logs against Oct 6. Old entries (single `w`/`r`, pounds)
  are read as one set and never rewritten. Completion is `log.done[plannedIso] = { at }`.
- Any published session can be opened and logged on any date; Today is a shortcut, not a lock.
  Unsaved input is kept as a draft across date changes and reloads. "Saved" is shown only after the
  write to localStorage succeeds.
- Not built: multiple attempts at one planned session (repeating a session adds sets to the same
  attempt), and exposure-based progression (weekly prescriptions follow the program week).

## Brand (see `_source/src/brand.jsx`)
- Source of truth: identity kit v1.2. `Mark`, `Wordmark` and `Lockup` use the kit's SVG paths verbatim.
  Never trace, redraw, recolour, outline, shadow or stretch the logo. Lockup is for 180px and wider.
- Lockup on the Home header and loading screen only, with "Strength for mountain athletes" once.
  `TopoField` (the supplied contour art) sits behind brand surfaces only, cropped bottom-right, away
  from text. The old brush wordmark, topographic pattern and drawn ridge silhouettes are retired.
- App icons in `icons/` come from the kit's dark app icon (`icon-192`, `icon-512`, `apple-touch-icon`);
  `assets/ridgeline-favicon.svg` is the favicon. The earlier `ridgeline_app_icon_*.png` files are kept
  but unused; they predate the kit's corrected mark.
- No photography is bundled. Use owned or licensed imagery only.

## Service worker
`sw.js` is network-first, so updates arrive the next time the app opens online. If you add a
new top-level file the app needs offline, add it to the `SHELL` list in `sw.js`.

## Known state
- Mountain Athlete Strength (v3.1) is the active program: all 12 weeks are written. Its default
  start date (2026-10-05) is a placeholder; the athlete sets their own in Setup. The Mountain
  Athlete Hybrid program is archived and was never edited apart from its status.
- Load progression is athlete-driven through the log. The weekly sets / reps / RPE tables follow
  the calendar week; the app does not hold a prescription back after a missed session.
- Older product docs (spec, UX flows, rules) describe the display-only Golden Leaf build. This
  file supersedes them where they conflict.
